# 小丑德州 · Joker Hold’em

独立的复古像素风扑克网页游戏，包含四种德州玩法，以及参考《小丑牌》玩法的独立单人闯关模式。四种德州玩法均支持 1–5 位 AI 对手，以及同一局域网内的手机、平板、Windows、macOS 和 Linux 浏览器联机。代码、依赖与素材均自包含，不依赖上级项目。

**在线游玩：[小丑德州 · GitHub Pages](https://joyinjoester.github.io/JOKER-HOLDEM/)**

打开网页即可单人游玩，也可以用「浏览器直连」邀请同一 Wi-Fi 下的朋友。不需要购买服务器、安装 Node.js 或运行后台程序。

## 无需自备服务器的局域网联机

1. 所有人打开在线游戏，在同一 Wi-Fi / 局域网内使用新版浏览器，并允许浏览器请求的本地网络访问。
2. 房主在「创建房间」选择「浏览器直连」，填写昵称、玩法、2–6 个座位及是否使用 AI 补位，然后创建牌桌。
3. 房主点击「生成邀请」，将完整邀请链接发给**一位**朋友。
4. 朋友打开邀请、填写昵称，点击「生成连接应答」，把应答复制发回房主，并保持当前网页打开。
5. 房主粘贴应答并点击「确认应答」。显示朋友已入座后，可以为下一位朋友生成新的邀请。
6. 人齐后房主点击「开始对局」。开启 AI 补位时，一个人也能开局；纯真人对战至少需要两位玩家。

每份邀请有效 10 分钟，只用于连接一位朋友；六位玩家需要房主依次邀请其他五人。手动交换邀请和应答是建立直连所需的步骤，六位房间号用于辨认牌桌，不能单独用于加入。邀请放在网址的 `#` 后，不会随网页请求发送给 GitHub。

连接通过 WebRTC DataChannel 直接同步，房主浏览器负责发牌和校验操作，只向每位玩家发送其可见的底牌。使用 Cloudflare / Google 的公共 STUN 服务辅助发现连接地址，以改善手机 Firefox 与电脑 Chrome 等设备组合的兼容性；STUN 不转发手牌或下注，没有信令服务器或 TURN 中转。公共地址发现不可用时仍会保留本地候选地址，GitHub Pages 只提供网页文件。局域网必须允许设备互访，访客 Wi-Fi、客户端隔离或浏览器权限限制可能阻止直连。这种方式不保证跨互联网连接。

**房主必须保持网页打开。** 房主刷新、关闭页面或退出浏览器会结束牌桌，直连模式不会自动移交房主；手机切到后台、锁屏也可能暂停连接。朋友短暂断线会尝试恢复；刷新后，可请房主生成新邀请，在**原来的浏览器标签页**粘贴邀请并交换新应答，回到原座位和当前牌局。关闭标签页会失去该页保存的重连凭证。

### 同一 Wi-Fi 仍然连接不上

部分浏览器只提供 `.local` 隐藏地址，而另一台设备无法解析这种地址；VPN / 代理虚拟网卡也可能影响发现和连接。

1. 双方刷新到最新版，取消之前的邀请。电脑创建牌桌后，点击房间上方的「连接帮助」。
2. 在「本机局域网 IPv4」中填写**这台电脑的真实 Wi-Fi 地址**，例如 `192.168.1.20`。在系统网络设置中查看 IPv4；不要填网关、网址或 FlClash 等代理网卡的 `198.18.x.x` 地址。
3. 返回连接并**生成新的邀请**，手机重新打开邀请、生成应答，再由房主确认。该地址用于下一次生成的邀请／应答，旧的连接信息不会自动更新。
4. 手机也可以在连接帮助中填写自己的 Wi-Fi IPv4，然后重新生成应答。不要在两台设备上填写相同地址；手机的地址可在当前 Wi-Fi 详情中查看。
5. 如果启用了代理 TUN，需允许局域网流量直连，或在测试时临时关闭 TUN。仍未连通时，可在「连接帮助」复制最近一次的连接诊断；报告只包含浏览器信息、连接状态和候选地址数量，不包含底牌、完整 IP、邀请密钥或应答密钥。

## 本地开发

开发环境需要 Node.js 22.14 或更新版本：

```powershell
npm ci
npm run dev:web
```

前端开发地址为 `http://localhost:5179`。构建纯静态文件并预览：

```powershell
npm run build
npm run preview:web
```

构建结果位于 `dist/`，包含所有代码、卡面与字体，可放在 GitHub Pages 等静态托管上。页面使用相对资源路径和 `#/` 路由，支持仓库子路径。

## 可选：电脑运行本地牌桌服务

也保留了原来的 Socket.IO 联机方式，适用于愿意在一台电脑上运行服务的场景。需要 Node.js 22.14 或更新版本：

```powershell
npm ci
npm run build
npm start
```

浏览器打开 `http://localhost:5178`。Windows 也可以双击 **启动游戏.cmd**；首次运行会安装依赖并构建。

开发本地服务时执行 `npm run dev`，前端修改会自动更新。修改服务器代码后需要重新启动。

1. 一台电脑启动服务，并保持终端运行。
2. 在本地网页选择「创建房间」→「本地服务」，填写昵称、玩法、2–6 个座位、是否使用 AI 补位及 AI 难度。
3. 将弹窗中的邀请链接发给同一 Wi-Fi / 局域网下的朋友。
4. 朋友用浏览器打开链接、填写昵称并加入。房主点击「开始对局」。

开启 AI 补位时，1–6 位真人都可开局；关闭后为纯真人对战，至少 2 人入座才能开局，空座不参与牌局。房主可在等候房间展开「房间设置」，修改玩法、人数、补位和难度，其他玩家会同步看到设置。只有运行服务的电脑需要安装 Node.js，其他设备只需要浏览器。网页会优先显示真实无线网卡地址，过滤常见虚拟网卡。

在本地服务模式中，刷新页面会使用本浏览器保存的凭证回到原座位，包括小丑商店中的装备与准备状态。断线后保留 30 秒行动时间，超时自动过牌、弃牌或在商店准备；房主离开或持续断线时会移交房主。主动离开的座位由 AI 接管，重新开桌时按房间设置安排座位。无人连接的房间保留 15 分钟。服务重启后联机房间会清空。

若其他设备无法连接，请检查是否同一局域网、是否开启 Wi-Fi 客户端隔离，并在 Windows 防火墙中允许 Node.js 访问专用网络的 TCP 5178 端口。不要将 `localhost` 或 `127.0.0.1` 发给其他设备。

可通过环境变量更改端口，例如 PowerShell 中 `$env:PORT=5180` 后执行 `npm start`。

此模式的参与者应打开电脑提供的局域网网址；GitHub Pages 不运行这项本地服务。直接打开 GitHub Pages 游玩时选择前面的「浏览器直连」。

## GitHub Actions 自动构建与发布

[Pages 工作流](https://github.com/JoyinJoester/JOKER-HOLDEM/actions/workflows/pages.yml) 在推送到 `main` 后自动安装依赖、运行规则测试、构建网页，并在独立 Chromium / Firefox 浏览器中验证静态子路径下的直连、多模式、六人牌局、重连和移动端布局。验证通过后自动部署 `dist/` 到 GitHub Pages。

PR 会执行构建与测试，不发布网站；也可在 Actions 中手动运行。仓库的 Settings → Pages → Source 使用 **GitHub Actions**，无需提交 `dist/` 或维护 `gh-pages` 分支。

## 玩法

大厅提供人机对战、创建房间和加入房间。人机可选择 1–5 个 AI 对手，难度有轻松、标准、挑战。返回大厅会暂停并保留人机进度，可以通过「继续上次的对局」恢复。新开一桌会替换人机存档。

| 模式     | 起始筹码 | 特殊规则                                                        |
| -------- | -------- | --------------------------------------------------------------- |
| 经典德州 | 2,000    | 标准无限注德州扑克，盲注每 4 手翻倍。                           |
| 小丑狂欢 | 2,000    | 持有小丑装备，局间购买、出售、刷新，叠加奖励；盲注每 4 手翻倍。 |
| 彩虹底池 | 2,000    | 摊牌获胜按牌型获得 1–10 倍底池份额；盲注每 4 手翻倍。           |
| 闪电战   | 500      | 盲注每手翻倍，快速决胜。                                        |

四种德州模式首手小盲 / 大盲为 10 / 20。盲注显示在「牌局信息」；点击当前模式名称可查看对应规则。

- 完整翻牌前、翻牌、转牌、河牌和摊牌流程；支持全押、多个边池、平分底池和奇数筹码分配。
- AI 使用自己的底牌与公共牌估算胜率，不读取对手底牌。
- 联机由房主浏览器或本地服务统一发牌、校验轮次与合法下注，并仅发送该玩家可见的牌。
- 人机进度、模式与人数设置、音量、CRT 效果、AI 难度和个人统计保存在当前浏览器。
- 快捷键：`F` 弃牌，`Space` 过牌 / 跟注，`R` 按当前金额加注，`Esc` 关闭弹窗。
- 手机上的「新开一桌」位于页脚。筹码为游戏内计分，不涉及真实货币。

### 小丑狂欢

首手赠送 1 张小丑和 4 枚小丑币。每手结束后进入商店，存活牌手获得 2 币，赢家额外获得 3 币；商店开门时，空装备的存活牌手还会获得一张小丑。小丑币与下注筹码分别计算。

| 小丑     | 效果                                            |
| -------- | ----------------------------------------------- |
| 幸运星   | 获胜时，额外获得所赢底池份额的 50%。            |
| 保命符   | 摊牌未赢得底池时，返还本手实际投入的 50%。      |
| 赏金头颅 | 获胜时向其他牌手各收取 1 个大盲，最多扣至零。   |
| 三叶草   | 以顺子或更大牌型获胜，额外获得所赢份额的 100%。 |
| 富翁     | 每次发牌前获得 5 个小盲的筹码补贴。             |
| 双面小丑 | 获胜份额翻倍；摊牌落败时返还全部实际投入。      |

购买 5 币、出售 2 币、刷新 1 币。最多持有 3 张，可叠加同款。三张公共货架由所有牌手共享，先买先得；刷新也会改变所有人的货架。准备后不能再改装备，所有存活玩家准备后自动发牌，AI 会自行购买并准备。联机由房主在每手结束后开启商店。

落败返还总额不超过本手实际损失，已退回的未跟注筹码不重复返还，弃牌不触发返还。奖励单独显示在结算面板；赏金在牌手之间转移，其他加成由牌桌发放。

### 彩虹底池

高牌 ×1，一对 ×1.2，两对 ×1.5，三条 ×2，顺子 ×2.5，同花 ×3，葫芦 ×4，四条 ×5，同花顺 / 皇家同花顺 ×10。按每位赢家实际获得的主池与边池份额发放额外奖励，完全相同的牌先平分底池再计算倍率。未跟注退款、无摊牌获胜均不获得倍率奖励。

### 小丑牌闯关 · 独立单人模式

从大厅点击「小丑牌闯关」，或打开 `http://localhost:5178/#/balatro`。选择起始牌组和挑战注级后开始冒险，使用有限的出牌与弃牌次数达到目标分数。每手选择 1–5 张牌，以「筹码 × 倍率」计分；只有组成牌型的牌及特殊效果参与计分。小丑从左向右触发，可调整顺序来组合加成。

- **闯关循环**：每个底注包含小盲、大盲和 Boss。小盲、大盲可以跳过并领取标签，Boss 必须挑战。击败第 8 底注 Boss 即通关，随后可继续无尽模式。
- **牌组构筑**：15 种起始牌组、8 种注级、150 张小丑、12 种牌型与对应星球、22 张塔罗、18 张幻灵、32 张优惠券、28 种 Boss 和 24 种标签。支持强化、版本、蜡封、重触发、复制效果及高注贴纸。
- **随机商店**：过关后领取奖励，购买或出售小丑与消耗牌、刷新货架、兑换优惠券，拆开丑角、天体、秘术、幻灵和标准卡包。多选卡包可以在选取途中存档。
- **每局不同**：默认生成新的随机种子，控制洗牌、商店、卡包、Boss、跳盲标签与概率效果。也可输入或掷骰子生成种子；使用相同种子、牌组、注级与操作可复现同一局。
- **自动存档**：手牌、商店、卡包、计分记录和随机状态保存在当前浏览器，刷新会恢复当前进度，不会重新抽取商品或卡牌。闯关存档与人机德州、联机凭证分开保存；不同设备与浏览器之间不自动同步。
- **计分动效**：出牌后依次展示牌型基础值、卡牌筹码、手持牌与小丑效果。触发的牌会高亮弹跳，筹码、倍率和总分逐步累加，最后计入本关得分，再补牌或进入过关／失败页。快速模式缩短播放时间，也可点「跳过」直接完成；减少动态效果时保留分步计分并关闭弹跳。动画中刷新会恢复已保存的结果，不会重复计分。
- **操作**：点击或触摸选牌，`1`–`9` 选择对应位置的手牌，`Enter` 出牌，`D` 弃牌，`Esc` 关闭弹窗。手牌默认按点数从 A 到 2 排列，发牌、补牌和改造后自动整理；可切换花色排序并随当前对局保存，也可手动移动卡牌调整计分顺序。可查看牌型、牌组、图鉴及本手完整计分过程，窄屏下玩法说明在设置中。

此模式可在电脑与手机浏览器单人游玩；局域网多人对战使用大厅中的四种德州玩法。当前闯关版开放全部卡池，未实现原作的解锁进度、成就与挑战列表。卡面和界面为原创像素绘制。

## 手机与不同屏幕尺寸

大厅、2–6 人德州牌桌、局间商店、联机等候房间，以及闯关的选盲、出牌、商店、卡包和结算按浏览器当前可见高度布局。常规游戏内容与主要操作放在同一屏；手机竖屏将信息栏移到上方，矮横屏将操作按钮移到手牌旁边。牌桌和卡面随剩余空间缩放，并为刘海与底部手势区域留出间距。

可以直接触摸选牌、拖动下注滑块，游玩中旋转屏幕不重新发牌、不清空已选手牌。闯关商店卡面可点击查看完整效果，矮屏下跳盲标签有独立详情入口。图鉴、规则和长记录在固定弹窗内浏览，关闭按钮保持可见；弹窗打开时游戏快捷键暂停响应。浏览器放大手势仍可使用。

## 验证

```powershell
npm test
npm run build
# 无需启动牌桌服务，测试脚本会临时托管 dist/：
npm run test:browser:p2p
# 先在另一个终端启动 npm start，再执行：
npm run test:browser
```

规则测试覆盖牌型比较、A 小顺、全押加注限制、边池、单挑顺序、四模式盲注、彩虹奖励、小丑叠加、返还上限与商店。随机对局验证「筹码总量 = 起始筹码 + 已发放奖励」；联机测试覆盖六座配置同步、底牌隔离、并发购买、商店准备、重连和房主移交。闯关测试覆盖全部小丑、Boss、消耗牌和优惠券，以及计分触发顺序、随机分布与复现、存档校验、牌堆耗尽、24 关通关与无尽模式。

浏览器测试默认使用本机 Chrome，包含桌面 / 手机大厅、2–6 人牌桌、人机完整牌局、四模式与商店操作、六个独立浏览器会话联机、刷新恢复和本地服务模式的房主移交，以及闯关模式的出牌、弃牌、商店、开包、图鉴、存档、胜负和触屏操作。`npm run test:browser:holdem` 单独检查德州，`npm run test:browser:modes` 单独检查多模式流程，`npm run test:browser:balatro` 单独检查闯关。

`npm run test:browser:p2p` 使用只提供文件的临时静态站点，验证真正的 WebRTC 连接、六人底牌隔离、错误应答拒绝、取消邀请、朋友刷新后重连、房主关闭、多模式结算及移动端邀请界面，并确认不会请求牌桌 API、Socket.IO 或 TURN 中转。额外测试拒绝隐藏 mDNS 地址的浏览器，确认显式 Wi-Fi IPv4 仍能联机与结算，并拒绝将代理虚拟网卡地址作为 Wi-Fi 地址。设置 `P2P_CROSS_BROWSER=1` 可额外验证 Chrome / Chromium 与 Firefox 互通；设置 `P2P_SITE_URL` 可在已部署的网站运行相同检查。CI 安装 Playwright Chromium / Firefox，并设置 `BROWSER_CHANNEL=chromium`。这些是独立浏览器会话及网络限制模拟，不能替代真实手机与路由器组合的验证。

`npm run test:browser:scoring` 检查实际计分时序、数字累加、卡牌与小丑高亮、阻止重复出牌、动画完成后结算、快速模式、减少动态效果、跳过与刷新恢复，以及不同尺寸下动画内容是否完整可见。

`npm run test:browser:viewport` 检查 14 种尺寸：320×568、360×640、375×667、390×844、430×932、568×320、667×375、844×390、768×1024、1024×768、1280×720、1366×768、1440×900、1920×1080。检查页面溢出、主要控件是否在屏幕内、牌桌元素重叠、弹窗操作、触摸命中和同一局横竖屏切换。可附加 `-- --quick` 只检查五种代表尺寸。

可用 `BROWSER_CHANNEL` 指定其他 Playwright 浏览器通道，`GAME_URL` 指定服务地址。截图和报告输出到 `test-results/`，尺寸报告位于 `test-results/viewport/report.json`。所有测试使用独立浏览器会话，不改动玩家现有存档。

- `src/GameHall.tsx`、`src/ModeControls.tsx`：大厅与人机 / 联机设置。
- `src/JokerShop.tsx`、`src/modes.css`：商店、装备、模式规则及六人布局。
- `src/App.tsx`、`src/Dialogs.tsx`、`src/styles.css`：牌桌、控制面板、弹窗及响应式界面。
- `src/viewport.css`、`src/useViewportHeight.ts`：可见屏幕高度、安全区域和德州 / 大厅的一屏布局。
- `src/visuals.tsx`：原创像素角色、扑克牌和背景着色器。
- `src/balatro/engine.ts`、`hands.ts`、`data.ts`：独立闯关规则、随机状态、牌型与卡池。
- `src/balatro/BalatroMode.tsx`、`RunSetup.tsx`、`RunBoard.tsx`、`Collection.tsx`：闯关入口、牌桌、商店、卡包和图鉴。
- `src/balatro/CardArt.tsx`、`balatro.css`：原创像素卡面与响应式布局。
- `src/balatro/viewport.css`：闯关各阶段、手牌和弹窗的一屏布局。
- `src/balatro/storage.ts`：闯关配置与存档校验。
- `src/network/rooms.ts`：两种联机方式共用的房间规则、身份恢复与权威牌局状态。
- `src/network/peer.ts`、`signaling.ts`、`protocol.ts`：WebRTC 连接、邀请应答、消息校验与重连。
- `src/network/connectivity.ts`、`src/PeerConnectionHelp.tsx`：公共地址发现、局域网 IPv4 备用连接和不包含连接密钥的诊断。
- `src/network/transport.ts`：浏览器内房间通信适配。
- `src/useNetwork.ts`、`usePeerNetwork.ts`、`useServerNetwork.ts`：直连与本地服务切换。
- `src/PeerLobby.tsx`、`NetworkChoice.tsx`、`peer.css`：邀请、应答、房间成员及移动端联机界面。
- `server/rooms.ts`：供 Socket.IO 使用的共享房间实现入口。
- `server/index.ts`：局域网 HTTP 服务与静态网页托管。
- `.github/workflows/pages.yml`：规则验证、浏览器直连测试、构建及 Pages 自动发布。
